# SQLx Compile-Time Query Checking

## How It Works

SQLx macro variants (`query!`, `query_scalar!`, `query_as!`) verify SQL at compile time. `sqlx-macros-core` 0.8 reads `SQLX_OFFLINE` and `DATABASE_URL` only after loading dotenv: `CARGO_MANIFEST_DIR/.env` when that file exists, otherwise `dotenvy::dotenv()`, which walks from the compiler's current directory through parent directories. Neither load overrides a variable that is already set.

This repo has no `crates/api/.env`. The walk finds the checkout `.env` (`DATABASE_URL=sqlite:quillai.db` in `.env.example`). A worktree under that checkout still finds the parent file. The URL is relative to the directory where Cargo was started, so the macros open that directory's `quillai.db`. A database that only has `users` then fails later-table queries (`no such table: chapters`, and the same for `series`, `books`, `lore_entries`, `author_guidance`).

When `SQLX_OFFLINE` is `true` or `1`, the macros skip the live database and use the committed `.sqlx/` cache.

## Setup

1. **Cargo.toml features**: `sqlx = { features = ["runtime-tokio", "sqlite", "macros", "migrate"] }`
   - `macros` — enables `query!`/`query_scalar!` compile-time checking
   - `migrate` — enables migration support
   - Note: sqlx 0.8.x has no `"offline"` feature flag. Offline mode is `SQLX_OFFLINE=true` plus the `.sqlx/` cache.

2. **`.cargo/config.toml`**: `[env] SQLX_OFFLINE = { value = "true", force = false }`. Every Cargo invocation (`cargo build`, `cargo xtask dev`, `cargo xtask lint`) compiles against `.sqlx/` without a shell export. `force` is false, so a variable already in the environment wins.

3. **`.env`**: `DATABASE_URL=sqlite:quillai.db` — used when offline mode is turned off for `cargo sqlx prepare`.

4. **`.sqlx/` directory**: Contains JSON query metadata generated by `cargo sqlx prepare --workspace`.

## Regenerating the Cache

When SQL queries change, point `DATABASE_URL` at a database with migrations applied (the shell or `.env`). `cargo sqlx prepare` runs that check with `SQLX_OFFLINE=false`. `force` is false, so Cargo keeps that value and the macros read the live database:

```sh
cargo sqlx database create
cargo sqlx migrate run
SQLX_OFFLINE=false cargo sqlx prepare --workspace
```

The `SQLX_OFFLINE=false` prefix is the explicit form. Prepare sets the same value itself, so `cargo sqlx prepare --workspace` also leaves the cache and checks `DATABASE_URL`. A normal build stays on `.sqlx/` until you opt out: `SQLX_OFFLINE=false cargo build -p quillai_api` (confirmed: a users-only database reports `no such table`).

## Offline Builds

Default, via `.cargo/config.toml`. `cargo build -p quillai_api` and `cargo xtask dev` compile against `.sqlx/` even when `DATABASE_URL` names a stale database.

## Important

- Use macro forms (`query_scalar!` not `query_scalar`) for compile-time checking
- `.sqlx/` directory **must** be committed to git (required for CI)
- `.env` and `*.db` are gitignored
- `.env.example` provides the template for local setup
