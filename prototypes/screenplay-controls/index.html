Screenplay controls in the rails

Static mockup. The row above the page (line type select, Download Fountain, Download FDX, New scene) is removed. Each control moves to the rail or drawer that already holds its prose equivalent. Nothing here is wired; hover and open states are drawn. Sample text is invented.

1 · Writing, 1440px, drawers closed

The header keeps only the app label and the path. There is no save label and there are no counts (see prototypes/editor-chrome). The right rail shows the current line type under the Continue icon, with its key. An empty line names its own type and the next Tab step, as placeholder text that is never saved.

Line type control: full 56px rail width · glyph 16px · value 10px ink · kbd chip "Tab" · not muted (it is a status) Empty-line hint: --pencil, CSS placeholder only, never in the Delta · text: "{type}" + Tab chip + "{next type in the Tab cycle}" Header: QuillAI label left, path "universe › script title" centred. No buttons, no save label, no counts. Right rail: Continue is an icon button (name and key in its tooltip); Help "?" sits above the gear.

2 · Line type menu, 1440px

Clicking the rail control opens the menu. It lists the six types in Tab order, says in plain words what each is for, and shows what Enter gives next. Clicking a row changes the caret line. It replaces the select.

Menu: 216px wide · right 64px · top 56px · popover shadow · rows in Tab cycle order (script_blocks.ts BLOCK_TYPES) "then" column = AFTER_ENTER map. Current row --pi-green (active tool). Esc, outside click or the rail control close it and restore the caret. Opening it closes either drawer (same rule as Settings).

3 · Manuscript drawer, 1440px: New scene and export

New scene is the + on the script row. Scenes are rows under the script. Fountain and FDX are a Script row in Exports, in the place of the Chapter and Book rows.

Script row + → "Add scene" (no menu; appends after the last scene, focus goes to the outline as for a new chapter) Exports while a script is open: Script [Fountain] [FDX] · Backup [Download]. Chapter and Book rows are hidden. Sheet: 760px, centred in the desk left after 356px (rail + drawer) and 56px (right rail).

4 · Line type menu, 1100px

Same menu, same place. The sheet is 700px wide here. The menu overlaps 72px of the sheet's 84px right padding and covers no text.

1100px closed: sheet 700px, 200px desk each side. Menu spans 64px to 280px from the right edge. Below 1100px: the line type control and menu move into the document flow with the rails, as other panels do.

5 · Manuscript drawer, 1100px

Drawer open at 1100px. The sheet is 640px and both edges stay visible. The line type control stays on the right rail; its menu would cover text here, so opening the menu closes the drawer first.

6 · How Enter and Tab teach the flow

Five steps of one exchange. Each panel shows the page, and the rail value at that moment. This is current behaviour (use_script_sync.ts Tab and Enter handling); only the hint and the rail value are new.

7 · Standard page, 1440px: one font, no toolbar, no repeated title

Every line is the script font at one size. The column is 60 characters wide, as on a US Letter page (6.0in of text at 10 characters per inch). Indents are counted in characters from the column's left edge. The formatting toolbar is gone. The rule above a scene shows the scene title only when it differs from the heading line under it. The dashed guides are drawn for this mockup only.

.ql-editor (script) : font var(--text-script)/var(--text-script-lh) var(--font-script) = 17px/1.2 · column width 60ch, centred in the 760px sheet (74px each side) action, scene heading : margin-left 0 · width 60ch · one blank line above (margin-top 1lh) character : margin-left 22ch · left aligned, not centred · uppercase · dialogue follows with no blank line parenthetical : margin-left 16ch · max-width 20ch · margin-top 0 dialogue : margin-left 10ch · max-width 35ch · margin-top 0 transition : text-align right · uppercase scene heading weight 400 (was 600). Uppercase stays display-only (text-transform); stored text is as typed. Toolbar: not rendered for a script. ⌘B ⌘I ⌘U still work. Break rule: title text only when title ≠ first heading line (trimmed, case-insensitive).

8 · Standard page, 1100px

Same 60-character column at 1100px. The sheet is 700px; the column is 612px and leaves 44px each side. With the manuscript drawer open the sheet is 640px, so the size steps down to 16px (column 576px, 32px each side). Line breaks do not change between the two sizes, because every width is in characters.

@container sheet (max-width: 659px) { font-size: var(--text-script-tight) } 16px · 1ch 9.6px · 60ch 576px Below 600px sheet width the column wraps early; page counts come from the 60ch model, not from screen wraps.

9 · Scrolled down the script, 1440px

The header has scrolled away and nothing is lost. The header holds only the app label and the path. The line type is in the right rail, which does not scroll, so it is still in view and still follows the caret (here on a Character line).

Rails: position fixed to the viewport (unchanged). Line type control reads the caret line on every selection change. Old top-bar select: removed (state 6 table). Nothing that reacts to the caret is left in the header.

10 · Continue streaming into a script, 1440px

Continue writes the next speaker and their line. The pin stays at the caret where Continue was pressed, with its gutter tick. Each streamed line lands in its own block type as it arrives: the name at the character indent, the parenthetical and the speech at theirs. Fresh text is AI ink (blue). The writing block marks the end of the stream. The rail shows Stop.

Block type while a line is still arriving: line 1 of the run = character · a line starting "(" = parenthetical · any other line = dialogue. Decided at the line's first character, so no line jumps indent mid-stream. Pin, gutter tick, writing block, --ai-ink, fade (1.5s hold, 10s to --ink): as prototypes/ai-interaction states 01–02. Overlays only; never Delta content. Editor is locked during the run (docs/editor-design.md:279). The line type control is dimmed and keeps the caret line's type. No model label on the page.
